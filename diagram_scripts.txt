// 10. ACTIVITY DIAGRAM (Order Placement)
// Concept: Flowchart-like diagram that illustrates the dynamic control flow from one activity to another, showing conditional logic.
// Creation: Created by translating the Java code inside OrderService.createOrder() into visual if/else paths (checking stock, processing payment).
// Usage: Used by developers to trace complex business logic and ensure edge cases (like rollbacks on insufficient stock) are accounted for.
// ------------------------------------------
stateDiagram-v2
    [*] --> ValidateUser
    ValidateUser --> CheckStock
    CheckStock --> CreateOrder : Stock Available
    CheckStock --> [*] : Insufficient Stock (Rollback)
    CreateOrder --> ProcessPayment
    ProcessPayment --> SaveToDB : Payment Success
    ProcessPayment --> CancelOrder : Payment Failed
    SaveToDB --> [*]

// 12. SEQUENCE DIAGRAM
// Concept: Shows how objects operate with one another and in what order chronologically, mapping messages passed back and forth along lifelines.
// Creation: Created by following an HTTP request down the Spring Boot stack (Client -> Controller -> Service -> DB) step-by-step.
// Usage: Very heavily used by backend engineers to debug API flow, see exactly where external calls are made, and verify transaction boundaries.
// ------------------------------------------
sequenceDiagram
    actor Client
    participant Controller as OrderController
    participant Service as OrderService
    participant PaySvc as PaymentService
    participant DB as PostgreSQL

    Client->>Controller: POST /api/orders
    Controller->>Service: createOrder(request)
    Service->>DB: Check Product Stock
    DB-->>Service: Stock Available (100)
    Service->>DB: Lock Row & Reduce Stock (-2)
    Service->>PaySvc: processPayment()
    PaySvc-->>Service: Payment SUCCESS
    Service->>DB: Commit Transaction
    Controller-->>Client: 200 OK (OrderDTO)
